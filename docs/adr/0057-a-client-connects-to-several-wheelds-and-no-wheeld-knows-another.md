# ADR-0057: A client connects to several wheelds, and no wheeld knows another

Clients federate: the Mac app, the iPhone and the `wheel` CLI each open one connection per server they are paired with and merge what those report in memory. No wheeld knows another exists; none forwards, mirrors or lists another's sessions. The design, with the Herdr and Rex comparisons, is `.wheel/artifacts/multi-server/index.md` (epic `wheel-2aln`).

A server's identity is a random id wheeld writes to the `server-id` file in its support directory on first start and reports as `status.host.id`; it never changes, and clients key servers, windows and preferences by it. wheeld also reports `name` (setting `server.name`, the hostname when empty), `color` (setting `server.color`, a macOS system colour) and `platform`. The remote listener's certificate fingerprint is not an identity: wheeld makes it only when the listener runs and remakes it every 365 days.

Each client keeps its own server list: the Mac in its preferences and Keychain, the phone in its Keychain, the CLI in `~/.wheel/servers.toml` with the credential in the macOS Keychain or a `0600` file on Linux. Each device pairs with each server once with that server's pairing code (ADR-0015), so each server revokes each device alone; the local wheeld is built in. The Mac app holds one connection per paired wheeld, shared by its windows: a window subscribes to its session's wheeld and reports its view there, a window record names its server, and Orchestrator mode subscribes to every server.

Servers are managed only in the session picker on the Mac and the phone: sessions listed server by server, **New Session** asking which server holds it, **Add Server…** at the bottom taking a pairing code. Settings edits the wheeld of the session the person is in. A server's mark is its system colour on a server glyph (`desktopcomputer` for a Mac, `server.rack` for Linux) beside its name, and with one server paired no mark is drawn.

The CLI's `wheel server` group (`list`, `status`, `add`, `rename`, `remove`, `enable`, `disable`) edits its list, and a global `--server <label-or-id>` sends any command to that wheeld. Ids are scoped per server, a failed connection does not prove a change was not applied, and `wheel --server <s> agent events --follow` streams that wheeld's agent events. A push carries `server` (the `host.id`), its collapse and thread ids start with it, and a tap opens that server's session.

Window commands stay on their own machine: a remote caller is refused pairing, device and window ops, so an agent on another server shows something with `--focus`. One orchestrator runs, on the always-on agent host, and every client's Orchestrator mode shows it; where a project lives is decided by its editable guidance, never recorded by wheeld or a client.
