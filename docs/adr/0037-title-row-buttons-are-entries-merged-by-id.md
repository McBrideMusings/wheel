# ADR-0037: Title-row buttons are `[[title.button]]` entries, merged by id

The title row shows its built-in buttons plus every `[[title.button]]` entry of this machine's `wheel.toml` and the space's, merged by `id`: the project's entry replaces the machine's with the same `id` where it stood, any other is added at the end. Unlike the single-source zones of ADR-0034 and ADR-0035, the two files add to each other.

An entry has `id`, `side` (`left`, the default, or `right`), `icon` (an SF Symbol), `tip`, `command` (run on a press; without one the button is an indicator), and, in this machine's file only, `state` with `every` seconds (default 5): a command whose last output line is a JSON object of `icon`, `tip`, `tint`, `badge` and `enabled`, laid over the entry. A project's `state` is ignored, so a repository runs nothing until a button of it is pressed; a press is refused while the button's command runs or its `state` printed `enabled: false`. `hidden = true` removes the built-in with that `id` (`sidebar`, `processes`, `palette`, `pin`, `new-space`). An entry with no `id`, a repeated `id`, a bad `side` or no `icon` is skipped and logged.

wheeld runs both commands through `/bin/sh -c` in the space's directory with no client attached (ADR-0020), reads both files every second, and sends `title_buttons_changed` when a space's list differs from the last one sent. The client draws icon-only buttons in fixed slots with the badge as an overlay, so a state change moves no neighbour. The ops and event raise `PROTOCOL_VERSION` and `ServerProtocol.current` together.
