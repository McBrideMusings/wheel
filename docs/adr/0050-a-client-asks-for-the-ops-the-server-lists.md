# ADR-0050: A client asks for the ops the server lists

This supersedes ADR-0020's protocol sentence. A server older than its client keeps serving it: only a change that breaks the protocol needs a restart.

`wheeld`'s `status` carries `ops`, the op name of every `ClientMsg` it handles, and `compat`, its compatibility level. `ops` comes from serde's list of `ClientMsg`'s variants (`wheel_proto::ops()`), so a new op is listed with no other edit. `compat` is the last level in `wheel_proto::BREAKS`, which names what each level changed. A level is added only when an op is removed, an op or field changes meaning, or a reply gains a field an older client cannot do without. Adding an op, or a field with a default, never adds one. `protocol` stays in `status` as a label for logs; nothing is decided from it.

A client connects only to a server at its own level. A server at a lower level gets a window that says "This Wheel needs a newer wheeld" and lists what the levels since changed; a server at a higher level gets "This wheeld is newer than this Wheel". Either way the window offers Restart Server. A server at the same level that lacks ops this client knows serves everything else. Restart Server then appears as a notice the person can close, the same notice a changed source hash brings.

Every frame a client sends passes one check against the server's `ops`: the GPUI client's connection thread, WheelKit's `DaemonClient.send` and the `wheel` command's `Conn::send`. A frame whose op the server did not list is not sent. Its request gets an `error` naming the op, and the client logs that a feature sent it without asking; the GPUI client also shows the error as a notice. A feature that sends an op asks first (`server_has` in the GPUI client, `ServerOffer.has` in WheelKit) and, when the server lacks it, stays in its place disabled or hidden with its slot kept. The `wheel` command refuses a server at another level, and an op the server lacks, naming the op.
