# ADR-0014: The Mac client owns its windows, and window commands reach it through wheeld

A Mac window is a main window or a little window, kept in the Mac app's own preferences; wheeld stores no windows and the iPhone has none. A main window is a list of space ids, an optional name and a sidebar flag; a little window shows one space and names the main window it belongs to, or none. A space is in one main window, in a little window, or in the background, where it keeps running and is listed in the menu bar item. A space in a little window that belongs to a main window keeps its tab there, and closing the little window returns the space to that tab; closing one that belongs to none returns the space to the background. Closing a main window that holds spaces asks whether to send them to the background, where its little windows stay open and belong to none, or to stop every process in them, which closes those little windows too; a main window closes on its own when its last space leaves. A new space opens in the focused window when wheeld makes it the active space, and in the background when it does not; focusing a background space opens it in a little window that belongs to none. The Mac app closes a background space once its last pane closes; a space in a window keeps one empty pane. A `wheel window` command goes to wheeld, which forwards it to the attached Mac app and returns the app's reply; with no Mac app attached the command fails and says so.
