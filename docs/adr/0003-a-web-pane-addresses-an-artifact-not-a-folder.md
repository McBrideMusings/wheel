# ADR-0003: A web pane addresses an artifact, not a folder

A web pane names an artifact by scope and name, never by a path. The name is looked up in a `wheel.toml` — the space's for scope `project`, this machine's `~/.wheel/wheel.toml` for scope `machine` — and that entry's `path` says where the page is: a folder, whose page is `index.html`, or one HTML file. A relative `path` is taken from the directory holding that `wheel.toml`. A path crosses the API only when an artifact is registered, and the daemon checks the entry then and every time it reads the file.

A pane serves from one root: the real folder, after following links, that holds the entry's real page. A request is served only when its file's real path is under that root and no component under the root starts with `.`; a `..` or an absolute path in the request is refused. So a page reads what sits beside and below it, never what a link inside its folder points out to, and an entry naming a folder outside a project shows a page the project did not write. The daemon writes into an artifact's folder only when `wheel artifact new` makes it.
