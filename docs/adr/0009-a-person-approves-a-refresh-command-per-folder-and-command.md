# ADR-0009: A person approves a refresh command, remembered per folder, project, command and the files it names

No refresh command runs until a person answers a permission request, the same request an agent's tool call raises. "Always" is remembered in `artifact-trust.json` in the instance directory, not in the saved layout, keyed by the artifact's folder (the real path ADR-0003 serves from, wherever its entry points), the space's directory and the command, so editing the command or pointing the entry at another folder asks again, and a machine artifact opened in another project is approved there on its own. An approval also records the SHA-256 of every readable file inside the artifact's folder or the space's directory that the command's text names, and holds only while the same files are there with the same contents: an edit, a pull or a branch switch that changes, adds or removes one asks again, and the request says which files changed. The daemon never judges what a program does with its arguments, so it keeps no list of interpreters or shell forms: every word of the command, read the way the shell reads it (quotes and backslashes removed, `$WHEEL_SPACE_DIR`, `$HOME` and a leading `~` expanded), and every piece of a word between `=` and `:`, is a path, opened the way the kernel opens it (links followed, then `..`). A relative path is looked up in the space's directory and in every directory inside the two that the command names, and a directory named there stands for the files directly in it. The panes' data directories, which every run writes, are left out. Not covered: code a named file reaches on its own (an import, a `Makefile`'s includes), a path built by another variable, a glob or a substitution's output, a file reached through a directory two levels down, and an edit that lands between the check and the run (on an on-demand refresh, that is the time the person takes to answer). Approvals are listed and forgotten by artifact name (`wheel artifact trust [--forget <name>]`).

A timer tick never raises a permission request: it runs only a command whose approval still holds and otherwise skips the tick, logging why, until it is approved again. The on-demand refresh is the path that asks. A pane's timer state (`off`, `ticking`, `untrusted`, `idle`, `stopped`) is computed on each read, not remembered.

A refusal, a non-zero exit, a kill by signal or the 60-second time limit is the run's recorded result, and the pane goes on serving its static files.
