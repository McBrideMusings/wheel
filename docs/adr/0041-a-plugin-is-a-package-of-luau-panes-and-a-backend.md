# ADR-0041: A plugin is a package of Luau pane scripts and a backend

A plugin is a folder holding a `wheel-plugin.toml` manifest, an optional backend process and optional Luau pane scripts: `[plugin]` (`id`, `version`), an optional `[backend]` (`command`, `transport`, `restart = "always" | "on-failure" | "never"`, `watch`, `needs`) and any number of `[[pane]]` (`id`, `title`, `script`, `reads`, `actions`). Machine plugins live in `~/.wheel/plugins/<id>/`, project plugins in `<project>/.wheel/plugins/<id>/`, built-ins in `wheeld`, and a backend the person runs themselves is an `[[external_backend]]` (`id`, `connect`) in a `wheel.toml` that `wheeld` reconnects to. A plugin runs only after the person approves its needs, reads and actions on a screen the client draws and no plugin can replace, and again whenever they change. This supersedes ADR-0028 and ADR-0026's `app`, `mcp` and `mcp_url` keys; ADR-0026's static artifact stands.

Each client runs each pane's script: `wheeld` sends script source and feed data, never a UI tree. `init(previous)` makes the state, `update(state, msg)` changes it, and `view(state, data)` returns a tree of WheelUI components and modifiers (ADR-0031, ADR-0038), which WheelUI draws natively on iOS and through the Swift bridge in the GPUI Mac client (ADR-0040). Input stays on the device and only actions go to `wheeld`. A changed script file reaches every client, which reloads it with its state kept; a script that fails leaves the pane on its last good view with the error in the pane header.

The VM is Luau's C and C++ sources vendored as a Swift package beside WheelUI in `apple/`, interpreter only, one VM per pane, locked with `luaL_sandbox`, with an instruction budget in the interrupt callback, a memory limit in a custom allocator, and no `io`, `os` or network globals. `docs/plugin-runtime.md` names the version, the build and the protocol crates.

Pane state lives in each client's memory (ADR-0022): a reload hands it to `init(previous)`, a client restart calls `init(nil)`, and state two devices share lives in a backend feed.

Backends speak Wheel's own JSON-RPC 2.0 with Content-Length framing, not MCP, over a unix socket `wheeld` assigns or stdio. `wheeld` supervises each one, restarting it per its `restart` policy, when a watched file changes, or on `wheel plugin restart <id>`, with every terminal and agent untouched. `wheeld` sends `initialize { wheel_version, plugin_id, config }` → `{ feeds, actions }`, `feed/subscribe`, `feed/unsubscribe`, `action/invoke { action, args, caller }` and `shutdown`; the backend sends `feed/update { feed, params, value | patch }` (`patch` is RFC 6902), `log { level, message }` and `wheel/call { method, args }`, checked against its approved needs. Spaces, panes, agents and settings are feeds `wheeld` publishes on the same path. A pane reads only the feeds in its `reads` and invokes only the actions in its `actions`, and shows a feed's last value marked stale while its backend is down.

Artifacts are static pages and posts only. Every process-backed artifact becomes a plugin, and `wheeld`'s MCP client for artifacts (`daemon/src/mcp.rs`), Wheelhouse's MCP server and process-served A2UI pages are deleted once each entry is ported.

The agent view is a built-in Luau plugin on the agent feeds (transcript, status, pending permission requests) and actions (send, answer), whose permission prompt is a component the client draws; the native GPUI and Swift agent views stay beside it. The orchestrator stays as ADR-0036 has it. The client ops for script sync, feeds and actions raise `PROTOCOL_VERSION` and `ServerProtocol.current` together (ADR-0020).
