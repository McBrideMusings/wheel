# ADR-0054: An orchestrator is an agent pane with a scope and an inbox

This supersedes ADR-0036.

An orchestrator is an agent pane that wheeld gives an inbox and the orchestrator brief. Its scope is a space or global: a space orchestrator is a pane in that space, a global one a pane in the Orchestrator space. It runs like any agent pane, with the person's settings and every tool they allow, and acts on any space or pane through the wheel CLI. Several may share a space. Each agent event goes to one orchestrator: the first started in the agent's space, else the first started global one. A space orchestrator is an agent too, so its own events go to the global orchestrator: space orchestrators report up. The inbox is a Maildir in the orchestrator's folder: wheeld writes each event about an agent routed to it, and each dispatch the orchestrator sends, as one file in `inbox/tmp` and renames it into `inbox/new`; nothing edits or deletes an inbox file. wheeld never starts a turn in an orchestrator's chat: when the person sends the orchestrator a message, wheeld attaches the files in `inbox/new` to it, marked as automated, and moves them to `inbox/cur`. For each new inbox file, and once when wheeld starts, wheeld runs the folder's `tools/on-event`. A global orchestrator's folder is the Orchestrator space's; a space orchestrator's is `~/.wheel/orchestrator/spaces/<space>`. Which orchestrator a person's voice reaches is the client's: the orchestrator pane it shows, else the first global one. ADR-0002's "Wheel runs no agent outside a pane" holds with no exception.

The process around the inbox lives in the folder's files, never in wheeld. `tools/on-event` keeps one `tasks/<id>.json` per dispatched piece of work, holding only inputs (what was asked, the agents, beads and PR it touches, the person's `done`, the last status pushed), recomputes each open task's status from the world on every run (`wheel status --json`, `gh`, `bd`), and sends `wheel push send --task <id>` when a task needs the person; the folder's `CLAUDE.md` and `docs/` hold the rules the orchestrator follows. wheeld only reads `tasks/` with the inbox events naming each task's agents (`orchestrator_tasks`, with `orchestrator_tasks_changed` when `tasks/` or `inbox/` changes), writes the person's `done` (`orchestrator_task_done`), and sends no per-pane push for an agent an open task names, so one event makes one notification.

ADR-0002's "no agent answers a permission request" keeps one exception: an orchestrator answers one when what the person said approves or refuses it, and `wheel perm answer` refuses to allow a request that cannot be undone from an orchestrator's pane until it passes `--confirmed`, which its brief says to pass only after the person said yes.

`orchestrator_start` takes the scope and, for a space orchestrator, the space the pane goes in, and replies with the pane and its agent; a space orchestrator runs in the `orchestrator.dir` setting of its space, else the space's folder. The pane's kind carries `orchestrator: space|global` and is saved, so a restored pane is an orchestrator again with its inbox as the folder holds it, its place in the start order the order wheeld restores panes in. A reloaded agent keeps its pane's folder and place. An orchestrator runs only as a chat: its pane refuses the terminal view, where Claude Code would run without the brief. `orchestrator_stop` names the pane.

The Orchestrator space is one space, in a session of its own named Orchestrator, where every global orchestrator's pane goes. wheeld makes it at the first global start and marks it `orchestrator` in the layout, so clients keep it out of the space tabs and Spaces mode; it is saved like any space and stays when every orchestrator stops. It cannot be closed or moved to another session, its session cannot be closed, and no other space joins its session: a space made from a pane in it joins the first other session. Its folder is the machine's `orchestrator.global.dir` setting, `~/.wheel/orchestrator` when empty, made when missing, where a global orchestrator keeps its own notes, tools and code; each global start moves the space to the setting's folder when it changed. A mirror in the Orchestrator space may show a pane of any session and closes when that pane closes; a mirror anywhere else shows a pane of its own session only.
