# ADR-0034: One source fills the window's bottom row: built-in usage, a text command, or an app

The row along the bottom of a Mac window shows exactly one source, chosen by the `[strip]` table of the space's `wheel.toml`, the project's over this machine's:

- **No `[strip]` entry: the built-in usage strip.** The client draws every shown harness's logins from the usage board. The person configures it without code: in the Usage window, each window a login's reading reports is a row with Strip, Pace and Reset toggles, and Settings › Usage chooses the labels. They are stored as `usage.pins`, `usage.pace`, `usage.resets` and `usage.labels` in this machine's `wheel.toml`. A toggle applies to every login of that harness. A login's folder name prints only when its harness has two or more logins.
- **`[strip] command = "<shell command>"`, with an optional `every` in seconds: text.** wheeld runs the command in the space's directory through `/bin/sh -c`, with the environment an agent pane gets, every `every` seconds and whenever the usage board or the space changes. It writes a JSON context to stdin: the space, its panes and agents, and the usage board. The row draws the last line the command printed, with its ANSI colours. `wheel strip usage --text` prints the built-in strip as such a line, so a command can include it.
- **`[strip] artifact = "<name>"`: an app.** The name is an artifact entry naming an `mcp` or `mcp_url` server (ADR-0026, ADR-0028). The row hosts the A2UI surface that server sends, drawn with the system controls and modifiers list (ADR-0031). Clicks go back as actions, and changes go back as ADR-0033 describes. No component is added for the row.

An entry that names both `command` and `artifact`, or neither, is a problem the settings listing reports, and the row shows the built-in strip.

The built-in strip takes its meters from each reading. wheeld reports every window a provider's answer carries, each with an id, a label, its percentage, its reset time and its length, and reports no window an answer leaves out. It assumes no fixed 5-hour and weekly pair. The Usage window offers toggles only for windows that exist. The pace tick is the share of the window's length that has passed by the reset time. wheeld reads every login of every harness it finds homes for, and reports each account's plan or billing and its email.

wheeld runs the command and the server, because a command must run with no client attached and against the space's directory (ADR-0020). The client draws all three. Choosing among the three, the new usage fields, and the `[strip]` table are a server change a client relies on, so they raise `PROTOCOL_VERSION` and `ServerProtocol.current` together.
