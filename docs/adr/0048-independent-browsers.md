# ADR-0048: A browser pane's Mac and phone browsers are independent

A browser pane has one WebKit browser on the Mac and one on the phone. Each has its own history, cookies, local storage and session storage. The page one is on, a login in one and a page's stored data pass to the other by no route, and the phone always draws its own page.

The only state the two share is the pane's home: the page the pane opens at, held in the layout as the pane's `url` (the wire and `spaces.json` keep that field name). A browser opens at the home when it is made and never navigates because the layout's `url` changed. It never reports where it goes, so wheeld holds no browser's current page and is sent none. Each client keeps the latest home the layout gave it, for its Home button (`goHome`).

A pane's home is set when it is opened: `pane_set_kind`, `pane_open` and `wheel pane kind|open <pane> --page <url> [--home <url>]` take an optional `home` beside the page. The home is `home` when given (a page given beside it is then not read), else the page given, else the `browser.homepage` setting, each read with `page_typed` and `page_allowed`. `wheel pane home <pane> [<url>]` (`pane_home`) prints the home, or with a page sets it: wheeld refuses a page a pane may not open, saves the home with the layout, logs the pane, the client that asked (a paired device's name, `mac` for the Mac app, `local` for the `wheel` command and agents) and the page, and sends the layout to every client but asks no browser to move. A client sets the home with the same `pane_home` and the page its browser is on. Both are refused for a pane that is not a browser pane.

wheeld asks a browser on demand. It sends the one browser it wants, chosen by `on` (`mac`, the default, or `phone`), an `inspect_pane` over the path `eval`, `dom`, `shot` and `record` use (`ask_clients`), and the browser answers. `wheel pane page <pane> <page> --on mac|phone` is one such ask: wheeld resolves the text with `page_typed` and `page_allowed`, then sends `inspect_pane` with action `open` and the page as its argument, and the browser goes there and answers with no text. With no phone attached the ask fails with "the phone is not attached". An address field sends `pane_browser_open` with no `on`: wheeld only resolves the text and replies `opened`, and the browser the person typed in goes there itself.

The phone still loads a page on the Mac's loopback through wheeld's `/loopback/<port>/` (ADR-0005). The cookies of those pages live in the phone's own web view store, kept by `LoopbackCookies`, because WebKit gives a custom scheme none.

This replaces the model in which the page and the logins follow the pane. `PROTOCOL_VERSION` and `ServerProtocol.current` go to 48 together (ADR-0020).
