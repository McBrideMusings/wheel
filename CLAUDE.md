# Wheel

A native macOS and iOS agent development environment: a grid of panes (terminals, agent chats, web views) per project, one space per project, all state held by a Rust daemon.

## Layout

- `daemon/` — `wheeld`, the Rust daemon (PTYs, agent sessions, spaces, permissions, artifacts). Its terminal emulator, `ghostty-vt`, builds libghostty-vt with Zig 0.16: `.cargo/config.toml` points cargo at `tools/zig`, which runs it through `mise` (installed on first use), so cargo needs `mise` on PATH and must run from inside the repo.
  A build from a fresh target needs the network twice: `ghostty-vt-sys`'s build script downloads Ghostty's source tarball, and `zig build` fetches Zig packages (`uucode`, `translate-c`) into `~/.cache/zig`. Offline works once both are local: extract the tarball named in `GHOSTTY.lock` (inside the `ghostty-vt-sys` crate in `~/.cargo/registry/src`) into a directory, export `GHOSTTY_SOURCE_DIR=<that directory>`, and build once online so `~/.cache/zig` fills. After that `cargo build --offline` succeeds with the network dead (checked: 51s from an empty target, proxies pointing at a closed port). An empty `~/.cache/zig` fails offline even with `GHOSTTY_SOURCE_DIR` set.
- `artifacts/` — the built-in artifacts `wheeld` embeds (one folder each, `builtin.toml` holding its version) and installs from Settings › Artifacts or `wheel artifact builtin`.
- `cli/` — `wheel`, the CLI over the daemon's socket; the programmatic surface every check drives.
- `apple/` — SwiftUI clients: shared `WheelKit` package plus the Mac and iOS apps (Xcode project generated by xcodegen).
- `docs/adr/` — decisions. Read ADR-0001 and ADR-0002 before changing how clients, the daemon or the agents fit together, ADR-0003 and ADR-0011 before changing what a web pane shows, ADR-0012 before changing how a pane switches between terminal and chat, ADR-0004 before changing what defines an artifact, ADR-0010 before changing how a post reaches its renderer, ADR-0009 before changing when a refresh command may run, ADR-0005 before changing what a browser pane may point at or where settings live, and ADR-0013 before making Wheel run, or expect to find on the machine, anything its app bundle does not carry.
- `DESIGN.md` — layout and visual direction. Early slices use stock macOS styling.

## Tracking

Work is tracked in beads (`bd`, prefix `wheel`). `bd ready` shows what is unblocked.

## Deploying Wheel from inside Wheel

`admin deploy` replaces the app you are running in. The running app, its terminals and the agent session that started the deploy stay up through the whole build; `macapp.Install` stops the app only for the two renames, then `open` relaunches it. Nothing may stop the app earlier. Because the stop kills the terminal that ran `admin deploy`, start it detached from the pane (`nohup` under `setsid`, output to a file) so the relaunch still runs after the stop. Never `pkill` Wheel, never run a step that quits it before the new build is finished and staged, and confirm afterwards that `pgrep -x Wheel` shows a process started after the install.
